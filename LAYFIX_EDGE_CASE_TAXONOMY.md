# Layfix edge-case taxonomy

This taxonomy groups **classes** of mixed-language / wrong-layout failures. It is derived from the live planner, tokenizer, and keyboard maps — not from one-off sentence rules.

Evidence: `npx vitest run` (315 tests) and `e2e/mixed-language-summary.json` generated by `src/adversarial/mixedLanguageCorpus.test.ts`.

No live Chrome/Edge session was run for this pass.

## 1. Language switching

A field may change intended language at token boundaries without an OS layout change.

| Pattern | Example | Policy |
| --- | --- | --- |
| AR → EN | `مرحبا hello` | Decide per token |
| EN → AR | `hello مرحبا` | Decide per token |
| AR → EN → AR | `مرحبا hello كيف` | Do not lock the sentence language |
| Rapid alternation | `مرحبا hello كيف are حالك you` | Local window only (radius 3) |

**Root cause if broken:** sentence-level language, or treating `sourceLayout` as intent.

## 2. Keyboard-layout mismatch

Script ≠ intent. The physical map is the only candidate generator.

| OS layout | Intent | Typed | Action |
| --- | --- | --- | --- |
| Arabic | Arabic | `مرحبا` | KEEP |
| Arabic | English | `اثممخ` / `بهىث` | CONVERT if mapped word is in the English lexicon |
| English | English | `hello` | KEEP |
| English | Arabic | `lvpfh` / `i,` | CONVERT if mapped word is in the Arabic lexicon |
| Arabic | alternating | mixed | Independent segments |

**Root cause if broken:** reverse remap commits only on a lexicon hit; missing high-frequency words look like “unknown Arabic.”

## 3. Mixed-language sentences

Correct mixed text must be a no-op.

| Pattern | Example | Policy |
| --- | --- | --- |
| Already correct | `مرحبا كيف حالك hello how are you` | NO-OP |
| Correct + wrong-layout neighbor | `hello بقهثىي how are you` | Fix only the mismatch |
| Partial run | `اثممخ xyzzy-on-Arabic` | Fix lexicon hits; leave OOV |

## 4. Context ambiguity

Same script can be a real word, a wrong-layout word, or unknown.

| Evidence | Action |
| --- | --- |
| Token is in the typed-script lexicon | KEEP |
| Physical remap is in the other lexicon | CONVERT |
| Both weak / OOV | NO-OP |
| Isolated 1–2 Latin letters | NO-OP unless local Arabic evidence exists |

Context is the previous 3 tokens + current + next 3, including already-remapped neighbors on a second pass. The rest of the page is ignored.

## 5. Tokenization

Whitespace splits first. Layout math/dash glyphs are delimiters, not letters.

| Input | Tokens |
| --- | --- |
| `hello world` | `hello`, `world` |
| `hello÷world` | `hello`, `world` (`÷` delimiter) |
| `hello-world` | `hello-world` |
| `hello_world` | `hello_world` (protected snake_case) |
| `hsjo]lj` | `hsjo]lj` (`]` is a letter on Arabic 101) |

**Root cause if broken:** merging `hello÷world`, or peeling `]` out of a QWERTY-Arabic word.

## 6. Punctuation

`، ؟ ؛ — – ! ? . ,` are boundaries. They do not change language by themselves.

`؛` peels as trail punctuation. QWERTY `,` / `;` / `` ` `` / `]` stay inside a token when they are Arabic 101 letters (`i,` → `هو`, `;dt` → `كيف`).

## 7. Symbols

`÷ × + - = / * & @ # %` are not words.

`÷` is Arabic 101 **Shift+I** and physically maps to `I`. Layfix still **does not** remap a symbol-only token. That avoids turning a real division sign into `I`.

`×` (Shift+O) and `—` / `–` are delimiters like `÷`.

`+ = / * & @ # %` stay inside a run so emails, URLs, and `hello+world` are not split.

## 8. Numbers

`123`, `2026`, `10:30` do not vote for a language. Digit-only tokens are protected.

## 9. URLs

`https://…`, `www.…`, `github.com/user/project` are skipped. Mixed sentences keep the URL untouched.

## 10. Emails

`user@example.com` is skipped. `@` is not a language switch.

## 11. Technical terms

`React`, `Laravel`, `Python`, `API` (ALL_CAPS), `getUserById` stay. ALL_CAPS / camelCase / snake_case are token-safety skips, not layout remaps.

## 12. Names

`John`, `محمد`, `OpenAI` are conservative: no lexicon hit → NO-OP. `OpenAI` is also PascalCase-protected.

## 13. Short tokens

`I`, `am`, `in`, `to`, `of`, `في`, `من`, `أنا`, `هو` must not be forced.

| Typed | Isolated | With local Arabic evidence |
| --- | --- | --- |
| `td` | KEEP | `في` |
| `kw` | KEEP | `نص` |
| `i,` | KEEP | `هو` |
| `÷` | KEEP | KEEP (symbol) |

## 14. Protected contexts

Password / OTP / PIN / CVV / card / email / URL / API key / JWT / UUID / hash / file path / code identifier / digits: NO-OP. See `src/safety/tokenKind.ts` and `src/safety/fields.ts`.

## 15. Editing behavior

Correction is planned on completed tokens (space / enter / tab / blur / `finalizeAll`). Character-by-character tests apply the planner after each space. Paste uses `finalizeAll`. The last in-progress token waits for a boundary.

## 16. Async / race conditions

Not re-measured in this corpus. Existing DOM snapshot / generation tests still apply (`src/adversarial/dom-races.test.ts`, `src/adversarial/accuracy.test.ts`). Local remap must not wait on usage IPC (`evaluateGate` `local-now`).

## 17. Performance

Planner cost is measured on the generated corpus (average **0.17 ms** / sentence in the executed run). Fields over **2000** characters or **48** tokens fall back to last-token-only in the content script so huge pastes are not rewritten wholesale.

## 18. DOM / editor compatibility

This pass did not drive a real page. Value inputs vs contenteditable vs IME composition remain covered by existing DOM tests only.
